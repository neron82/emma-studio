## 0. Executive summary

The realtime core (OpenAI-Realtime protocol translation, speculative-turn machinery, SESSION_END drain/quarantine lifecycle) is in good shape — the audit found **no protocol-level race** in it. The defects that mattered were concentrated in **Emma's own glue layer** and in **orthogonal modules**, and the biggest structural finding is that the repo currently carries **two complete, parallel conversation stacks** whose older half is now unreachable from the web app.

Three **behavioural** defects were fixed — the most consequential being a stale background web search that silently overwrote the next turn's prompt, degrading answer quality with no visible symptom. Three **maintainability** defects were fixed by de-duplication and a lint pass. 972 lines were removed (758 from two deleted files, the remainder dead definitions, unused imports and rewritten comments) plus a 14.4 MiB backup binary. Two deliberately-built features that could never execute (a transcript-logging privacy gate and the per-pipeline log prefix) were wired up instead of deleted.

The remaining work is **structural, not incidental** — see §5. The headline items: the per-persona VRM selection is write-only, and the legacy batch pipeline should either be adopted or retired before 1.0.

## 1. Method & baseline

**Environment.** The audit ran in the project environment (Python 3.12, with torch, faster-whisper, onnxruntime and moondream installed). `pyproject.toml` has no ruff config and the repo is not ruff-formatted; lint was used as a *signal*, never as an autoformatter for the tree.

**Baseline.**
```
python -m pytest tests/ -q   →   53 passed
```

**Techniques.**

1. **AST import graph + reverse reference scan** over every `.py` (plus `.js`/`.html`/`.sh`/`.toml` for symbol mentions) to find modules and definitions with zero referrers. Every candidate was re-verified by hand before deletion — see the methodology note below.
2. **`ruff check --select F,E,W,B,SIM,C4,UP,RET,ARG,PIE,PERF,RUF`** → 321 findings, of which the `F`-family (unused imports/variables, undefined names, syntax) were acted on; `ARG`/`RUF100`/`UP*` were reviewed and mostly intentional.
3. **Line-level reading** of every concurrency-sensitive file: `deliver/realtime/{service,websocket_router,pipeline_unit,transports,handlers/*}.py`, `speech/engine.py`, `speech/{chat,vad_handler,lm_output_processor,silent_turn_processor}.py`, `speech/core/{cancel_scope,speculative_turns,control,thread_manager}.py`, `web/static/js/{call-session,facetime-engine,backchannel}.js`, `web/static/worklets/*.js`.
4. **Independent read-only recon pass** (subagent) over the frontend/REST surface and config knobs.
5. **Behavioural verification** of each fix with throwaway scripts (§6), not just test-suite green.

> **Methodology caveat worth keeping.** The independent recon pass reported one "certain" finding that verification disproved: it claimed `Chat.to_responses_api_chat` *and its private body* were dead. The private body `_to_responses_api_chat_locked` is in fact **live** — it backs the compaction snapshot (`_snapshot_for_compaction`, `chat.py:963`). Acting on that report unverified would have deleted the compaction serializer. Every deletion in this audit was confirmed against actual call sites.

**Not exercised** (needs the live stack): a full end-to-end WebSocket call. `engine.build_into` requires whisper + LLM + OmniVoice; with any of them down the route correctly surfaces `engine_unavailable` and closes with `1008`. Protocol behaviour is covered by `tests/test_realtime_protocol.py`.

## 2. Defects fixed

### 2.1 Race — a stale background web search overwrote the *next* turn's prompt
**Where:** `studio/speech/engine.py:787` (`_refresh_instructions`), state at `:309`
**Cause:** The SearXNG fallback runs on a daemon thread because a blocking web call would stall the send loop's audio delivery (correct decision). That thread then assigns `cfg.session.instructions` — the same mutable field the *next* turn builds from. There was no ownership check, so a 15 s search result landing after the next turn's refresh silently replaced fresh fact cards (and the injected camera context) with stale ones.
**Fix:** Each turn stamps a per-connection prompt generation (`_prompt_generation`, cleared in `unregister`). The worker applies its result only if its own turn is still the newest; otherwise it drops it and logs at debug level.
**Evidence:** stub `search_sync` that blocks on an event — with turn 2 issued while turn 1's search is in flight, the stale result is discarded and turn 2's facts survive; a same-turn result still applies.

### 2.2 Silent turns corrupted connection state when the prompt queue was absent
**Where:** `studio/speech/engine.py:607` (`_maybe_silent_turn`), guard now at `:617`
**Cause:** The `text_prompt_queue is None` guard sat *after* the method had already (a) replaced `session.instructions` with the silent-turn framing, (b) inserted an ephemeral user turn into the chat, (c) recorded `_silent_keys` / `_silent_user_items`, and (d) called `mark_response_pending(...)`. The early return therefore leaked a pending response key and an orphaned chat item, and left the silent framing installed for the next real turn.
**Fix:** Guard hoisted to the top; the redundant duplicate check removed.
**Evidence:** `text_prompt_queue=None` service — `response_pending` stays `False`, no silent bookkeeping, instructions untouched.

### 2.3 Fact-card lookup computed and discarded in the video pipeline
**Where:** `studio/core/pipeline.py:35` (`_script_video_message`)
**Cause:** `facts = store.search_facts(...)` (a hybrid FTS + embedding round-trip) was assigned and never used — `ruff F841`. Consequence: video-message scripting ran from the bare personality prompt and omitted the persona's fact cards, while the dialog path included them.
**Fix:** Facts are now rendered into the scripting system prompt, mirroring the dialog framing.
**Note:** verified statically (the prompt assembly is pure string building); the full render path cannot run here (needs ComfyUI).

### 2.4 Duplicated SearXNG fetcher
**Where:** `studio/speech/engine._web_search_sync` (deleted) vs `studio/agent/search.search`
**Cause:** `_web_search_sync` was self-documented as a "mirror of `studio.agent.search.search`" — two httpx SearXNG clients with identical query/param/result-shape logic, so a fix to one silently skipped the other.
**Fix:** One implementation. `agent/search.py:17` is `search_sync` (used by pipeline threads); `:38` is a thin `asyncio.to_thread` facade for the batch path. Behaviour preserved (returns `[{title, snippet}]`, empty list on any failure).

### 2.5 Duplicated filler URL construction, unquoted
**Where:** `studio/deliver/app.py:150` vs `studio/speech/backchannel.py:138`
**Cause:** The route hand-rolled `entry['file'].split('/', 1)[1]`; `backchannel.filler_url` did the same plus `urllib.parse.quote`. Two copies, one of them wrong for filenames needing escaping.
**Fix:** Route calls `backchannel.filler_url(entry)`.
**Evidence:** end-to-end — manifest → `POST /api/fillers/pick` → returned URL resolves to the clip bytes (200). Latent, because the frontend has the filler call disabled (`FILLERS_ENABLED=false`), which is exactly why it would have rotted unnoticed.

### 2.6 Stale and unused imports (15 findings across 12 files)
Auto-fixed `F401`/`F541`, plus 3 `F841` by hand. Notably:
- `studio/deliver/realtime/service.py` imported `EmmaStatusEvent` alongside `EmmaVideoFrameEvent` and never used it (only the video-frame event is consumed there).
- `studio/core/pipeline.py` imported `asyncio` and `random` unused; `store.py` `json`; `render/comfy.py` `copy`; `speech/router.py` `httpx` + `config`; `speech/backchannel.py` `time` + `Path`; `speech/tts.py` `time`; `app.py` a local `pathlib.Path`.
- `studio/speech/utils.py` imported `requests` — **not a declared dependency** — solely for a dead helper (see §3).

## 4. Orphaned pathways *restored* rather than deleted

Two features were built deliberately and then left unwired — dead switches, not garbage. Both are now live.

**4.1 Transcript-logging privacy gate could never be enabled.** `speech/core/transcript_logging.py` documents `--log_transcripts`; no such flag existed, and `set_log_transcripts` was never called, so the opt-in debugging path was unreachable (and `warn_if_log_transcripts_enabled` — the loud "you are now logging conversations" warning — never fired). Wired as `STUDIO_LOG_TRANSCRIPTS=1` read in `app.py:59` (covers the systemd/uvicorn entry) plus `--log_transcripts` in `__main__.py:28` (the documented module entry). **The privacy default is unchanged: content off, character counts only.**

**4.2 The per-pipeline log prefix could never appear.** `log_context.py`'s whole docstring promises a `[pipeline N]` tag on every record, but `PipelineLogFilter` was never attached to anything — only the contextvar was set. Attached in `app.py:50-55`. The subtlety that makes this easy to get wrong is documented in the code: the filter must go on the **handlers**, not the root logger, because records propagating up from child loggers bypass ancestor logger filters.

Verified: `[pipeline 3] bound` / `unbound` for bound vs unbound context, and `chars=11` (not the text) for the transcript gate at default.

**4.3 Documentation/code drift corrected.** Two docstrings referenced `ResponsesApiModelHandler`, a class that no longer exists (`base_openai_compatible_language_model.py:146`, `chat_completions_language_model.py:279`). `backchannel.js` documented a `stopIfPlaying()` method that was never implemented. The README's test command used `.venv/bin/python`, which did not exist in the deployed environment — corrected, and the new log gate documented.

## 5. Restructuring backlog (beta → 1.0)

Prioritised. Each item is a decision or a structural change, not a defect — that is why it was not actioned unilaterally.

### P0 — decide before 1.0

**5.1 The persona VRM selection is write-only.**
`personas.vrm_model` is in the schema (`store.py:29`), migrated, settable via `POST/PATCH /api/personas` (`app.py:193`), returned by the API and rendered in the Personas view (`index.html:353`, `VRM ${p.vrm_model||'—'}`) — but **nothing reads it to choose a model**: `facetime-engine.js:99,103` hardcodes `/static/avatars/emma.vrm`. `web/static/avatars/default.vrm` (11 MiB) exists for exactly this purpose and is referenced by nothing since the legacy template was removed.
*Options:* wire it (server passes the model URL per persona, engine loads it) or drop the column + UI field. Either way, one of the two must go before 1.0 — a UI that reports a setting which has no effect is a support trap.

**5.2 Two parallel conversation stacks.** The repo contains the live realtime path *and* a complete legacy batch path:

| Legacy piece | Reachable from |
|---|---|
| `core/pipeline.py` (`run_call_turn`, `run_video_message`) | Telegram `--telegram`; `scripts/bench_e2e.py` |
| `agent/dialog.chat`, `agent/search.search` | `pipeline.py` only |
| `speech/{chunks,router,tts}.py`, `render/comfy.py` | `pipeline.py`, `scripts/gen_fillers.py` |
| `POST /api/jobs/turn`, `/api/jobs/*` GETs, in-memory `_histories` (`app.py:81,235,243`) | `scripts/bench_e2e.py` only — its web UI (`facetime.html`) is gone |
| `_histories` itself | superseded by the `messages` table, which is the live history source |

The web app no longer touches any of it. Telegram still does, and the video-message module is documented in the README as "Modul fertig, Anbindung offen". So this is a **deliberate decision point**: either adopt it (wire `/api/jobs/video` into the UI, retire `_histories` in favour of the DB) or retire it (and with it `--telegram`'s dialog turns). It should not survive into 1.0 as an unreachable third state.

**5.3 Uncalled REST surface.** Provably no caller in repo, frontend, or scripts: `GET /api/sessions` + `/api/sessions/{id}` (`app.py:388,394`), `POST /api/jobs/video` (`:227`), `POST /api/stt` (`:168`), `GET /api/jobs` list (`:257`), `GET /api/jobs/{id}/video` (`:298`). Some are the documented integration points of 5.2 (keep with it, drop with it); `/api/sessions*` looks like a forgotten read API for the call history that the UI shows via `/api/history`.

### P1 — hygiene with real cost

**5.4 Dead cluster in the ported realtime core** (verified definition-only, kept in this pass to avoid churn in vendored-style code):
- `RealtimeService.should_defer_pipeline_event` (`service.py:532`) and its only callee `SpeculativeTurnTracker.has_pending_reopen_or_grace` (`speculative_turns.py:146`)
- `SpeculativeTurnTracker.has_pending_reopen` (`:140`), `try_is_latest_after_pending_reopen` (`:63`), `try_commit_if_latest_after_pending_reopen` (`:112`)
- `RealtimeService.try_dispatch_pipeline_event` (`:524`), `RealtimeService.connection_ids` (`:373`)
- `Chat.to_responses_api_chat` (`chat.py:630` — the public wrapper only; its `_locked` body is live and backs compaction)

**5.5 Dead package facades.** `studio/speech/core/__init__.py` re-exports 30 names and is consumed by nothing (`from studio.speech.core import …` occurs zero times — every consumer imports a concrete submodule); `studio/agent/__init__.py` likewise. Harmless, but they rot silently and misrepresent the public API.

**5.6 Cross-session status channel is not session-scoped.** `engine.py:290` holds one `_status_pending` deque for the whole service, and `drain_status_events(conn_id)` ignores `conn_id` entirely (`:448-455`). With the shipping `REALTIME_POOL_SIZE=1` the practical effect is that a released session's queued status lines surface in the *next* session's debug overlay; with pool size > 1 the channel mixes sessions. It is display-only (no protocol or audio effect), but it is the one place where the pool's session isolation is not honoured — worth fixing when the pool is ever raised above 1.

**5.7 SQLite is shared across threads without a lock.** `store.py:132` opens one connection with `check_same_thread=False`, and it is written from the send loop, the VLM analyzer, request handlers and the memory thread. Safe on this build (`sqlite3.threadsafety == 3`, serialized), and the class docstring argues "single-user, contention is a non-issue" — but the implicit transaction is shared across threads, so a failure in one writer can roll back another's uncommitted statements. Either add a write lock or document the constraint; do not leave it implicit.

**5.8 Residual analyzer-thread window (bounded).** `EmmaRealtimeService.unregister` pops the per-conn dicts (`engine.py:387-390`) while the VLM analyzer thread may still be inside `_analyze_once`, which can re-create `_cycles[conn_id]` / `_pending_cycles[conn_id]` after the pop. The consequences are bounded (a small dict entry per session, plus one `Analyzer-Fehler` warning) and I verified the more serious variant is *not* reachable: no stale silent-turn request can leak into the next session, because `_persona_for` returns `None` once `_persona_by_conn` is popped, and the `_conns` entry is only removed afterwards by `super().unregister`. Worth a generation check if the analyzer ever grows new state.

### P2 — repo hygiene

**5.9 Unreferenced large assets still tracked (20 MiB).** After the `facetime.html` removal these have no referrer at all: `web/static/avatars/default.vrm` (11 MiB — see 5.1), `tests/display.glb` (9.3 MiB) and `tests/emma2.vrm` (96 KiB, the latter two are `glb_to_vrm.py` artefacts). Not deleted unilaterally — they are content, not code, and `default.vrm` is the asset 5.1 would need. Note also that `emma.vrm.bak` (14.4 MiB) remains in git *history* even though it is gone from the tree; a 1.0 that cares about clone size should consider a history rewrite.

**5.10 Nothing runs in CI.** `tests/` contains four pytest-uncollected files (`view_contract.py`, `avatar_functional.py`, `avatar_functional.js`, `lipsync_e2e.js`) — all are manual headless-Chrome probes, and `avatar_functional.py` still imports three.js from a CDN while the app vendors it. `scripts/*.py` are referenced by nothing — no Makefile, no README mention. Either wire them up or mark them clearly as manual.

**5.11 Stale build metadata.** `emma_studio.egg-info/SOURCES.txt` lists `studio/core/stream_pipeline.py` (does not exist) and omits nearly all current modules. Gitignored, so harmless — but regenerating it avoids future confusion.

**5.12 Minor heuristic nit (and a third duplication).** `_looks_like_question` exists twice — `engine.py` (over `_QUESTION_MARKERS`) and `core/pipeline.py` (over a local `markers` tuple with identical entries; the pipeline copy also dropped the `config.SEARCH_ENABLED` short-circuit into the caller). Both do substring matching, so markers like `"wie "` fire on *irgendwie*, sending an unnecessary SearXNG query. Consolidating the two — as was done for the SearXNG fetch itself in §2.4 — plus a word-boundary test would fix both at once. Not a release blocker.

## 7. Confirmed **not** bugs (so they don't get "fixed" later)

Recording these deliberately — each looks wrong at a glance and each was verified sound:

1. **`search_facts`' boost expression** (`store.py:288`): `1.0 if not r["persona_id"] or r["persona_id"] == persona_id else 0.0` reads as if it never distinguishes persona-scoped from global facts. It is behaviourally correct: the SQL already orders persona-scoped first, and the constant boost serves to keep keyword hits above the capped semantic-only hits (max 0.9 by design in `_semantic_search`). I changed this, then reverted it after checking the call sites — only the comment was wrong. `tests/test_core.py::test_facts_fts_and_scoping` defends the documented ordering.
2. **`CancelScope` is lock-free on purpose** (`core/cancel_scope.py`): single writer (router task), multiple readers (handler threads), int/bool only. Sound under the GIL as documented; do not add a lock.
3. **`_maybe_silent_turn`'s `_state(conn_id)` cannot `KeyError`** during teardown: `EmmaRealtimeService.unregister` pops the Emma-specific dicts first and only then delegates to `super().unregister`, which is where `_conns` is popped — and `_persona_for` gates entry to `_state` anyway.
4. **The SESSION_END drain/quarantine design holds** (`websocket_router.py`): the unit stays claimed until SESSION_END traverses the handler chain back to `output_queue`, which is what prevents a force-released session's output (transcripts carry no session identity) from being published into the next session. Quarantine-after-180 s is the deliberate failure mode, visible as `"stuck"` in `/v1/pool`.
5. **`web/static/worklets/audio-playback.js`'s `clear` does not stop instantly** — it fades over 32 frames by design (a hard cut clicks). The theoretical window where new audio arrives mid-fade is sub-millisecond and unreachable given the client latches incoming deltas until the next `response.created`.
6. **`_normalize_ordered_parts`** appears twice with zero call sites — both are pydantic `@model_validator` hooks, invoked by the framework.
